# JavaScript 事件循环

## 前置知识
### js 线程
1. js 默认只启用一个线程执行
2. 代码中有 耗时任务与不耗时任务，v8 在执行的时候，遇见耗时任务，会将其暂时挂起
- **耗时任务**
> webworker()，v8可以调用这个函数，强行开启多线程

3. **为什么不设计成多线程**

- js 可以操作 doom 结构(document)，可以跟 html 深度合作，获取其容器并操作。多线程可能会造成不安全的渲染
- 如果要设置成多线程，就需要用到 锁。增加了难度，增加了设备性能开销

## 事件循环
### 任务
1. 耗时任务 (异步任务) 被存放在**队列**中，先执行不耗时任务(同步任务)
> 有些异步任务并不耗时，官方从底层规定了叫异步任务。因此**不能说** 耗时任务 就是 异步任务。

- 由于放在队列中，随着版本更新，分类还不够细致，因此异步任务后来被再次拆分 
1. 宏任务 例如 `setTimeout()`  `<script>` `setInterval()` `ajax` `I/O` `UI-rendering`
2. 微任务 例如 `promise.then()` `process.nextTick()` `MutationObserver`


> 1. `promise.then()` 才是异步，`promise()`不是哦
> 2. `setTimeout()`隔一段时间才执行一次
> 3. `setInterval()` 每隔一段时间执行一次

### setTimeout()
- 所有的 `setTimeout()` **共用一份时间**，先进宏任务队列的不一定先执行。而是根据计时时间长度来判断是否先执行，计时时间短的先执行。(这是浏览器的任务队列)

> 定时器被创造之后 浏览器会给定时器都分配一个 id，这些 id 以耗时短为基准存入额外的一个队列中，时间短的先存进去

### 事件循环机制
1. v8 会按照 同步任务->异步任务的顺序执行，遇到异步就存入对应的队列中
2. 异步任务又细分为 宏任务 与 微任务，执行时 先去 微任务队列 中查找 微任务，并取出来执行。
3. 去宏任务队列中查找宏任务，并将宏任务取出执行。
4. 如果宏任务中又嵌套了其他逻辑，则按照上面三步循环
- v8 开始执行同步任务，这本身属于 同步任务

### JS引擎线程 和 渲染线程
- JS 引擎线程 v8 和浏览器渲染页面的 渲染线程 是互斥的，只能跑一个
> 原因和 js 引擎是单线程的类似

- script 标签是宏任务

## async/await
1. 函数前面加 `async` 等同于函数内部 `return` 了一个 `promise`对象
2. `await xxx`中`xxx`看作同步来执行 ，`await`会将 它后续的代码挤入微任务队列
