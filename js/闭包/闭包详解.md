## 一、前置知识：作用域链与词法作用域

在理解闭包之前，需要先搞明白两个概念：**作用域链**和**词法作用域**。

### 1.1 作用域链

每一个执行上下文的变量环境中都存在一个 `outer` 指针，用来指向外部的执行上下文。当 V8 在查找一个变量时，在当前执行上下文中没有找到，就会顺着 `outer` 所指向的那个执行上下文查找，以此类推，直到找到全局为止。我们把这个查找的链条称为**作用域链**。

看一个例子（[1.js](file:///f:/AAAAIFullStackDevelop/js/闭包/1.js)）：

```js
let count = 1
function main(){
    let count = 2
    function bar(){
        let count = 3
        function foo(){
            console.log(count)
        }
        foo()
    }
    bar()
}
main()
```

输出：**3**

查找过程是这样的：

```
foo() 内部查找 count
  → 自己的作用域有没有？没有（let count = 4 被注释了）
  → bar() 的作用域有没有？有！count = 3 → 输出 3，停止查找
```

这就是作用域链的查找规则：**从内到外，找到即止**。

### 1.2 词法作用域（静态作用域）

再看一个例子（[2.js](file:///f:/AAAAIFullStackDevelop/js/闭包/2.js)）：

```js
function bar(){
    var myName = 'sai'
    let test1 = 100
    if(1){
        let myName = 'fan'
        console.log(test)   // 这里的 test 是？
        console.log(myName) // 这里的 myName 是？
        console.log(myAge)  // 这里的 myAge 是？
    }
}
function foo(){
    var myName = 'ggbond'
    let test = 2
    {
        let test = 3
        bar()
    }
}
var myName = 'tao'
let myAge = 18
let test = 1
foo()
```

输出：

```
1    （test 来自全局，因为 bar 定义在全局）
fan  （myName 来自 if 块内的 let myName = 'fan'）
18   （myAge 来自全局）
```

**关键规则：JavaScript 采用词法作用域（静态作用域），函数的作用域在函数声明时就确定了，而不是在调用时确定。**

`bar()` 函数声明在全局，所以它的外部作用域就是全局作用域。即使在 `foo()` 内部调用 `bar()`，`bar()` 也访问不到 `foo()` 的变量。

## 二、什么是闭包

### 2.1 从代码入手

先看一个最经典的例子（[3.js](file:///f:/AAAAIFullStackDevelop/js/闭包/3.js)）：

```js
function foo(){
    var myName = 'zhang'
    var age = 18
    function bar(){
        console.log(myName)
    }
    return bar
}
var baz = foo()
baz()
```

输出：**zhang**

这段代码做了什么？

1. `foo()` 执行，内部声明了 `myName`、`age` 和一个内部函数 `bar`
2. `foo()` 把 `bar` **返回**了出去，赋值给全局变量 `baz`
3. `foo()` 执行完毕，按理说它的执行上下文应该被销毁
4. 但我们调用 `baz()` 时，依然能打印出 `myName` 的值

**这就是闭包：foo() 虽然执行完了，但 bar 函数引用了 myName，所以 myName 被保留了下来。**

### 2.2 闭包的定义

> 当**一个外部函数中的内部函数被拿到外部函数之外来执行**，哪怕外部函数执行完毕了，**被内部函数引用的那部分变量依然需要保留**，我们把这部分变量的集合称之为闭包。

更准确地说：

> **闭包 = 内部函数 + 内部函数所引用的外部变量的集合**

### 2.3 闭包的形成条件

三个条件，缺一不可：

1. **存在函数嵌套**（一个函数里面定义另一个函数）
2. **内部函数引用了外部函数的变量**
3. **内部函数被带到了外部执行**（return 出去、push 到数组、作为回调等）

## 三、闭包的三种写法

### 3.1 函数 return 函数（最常用）

```js
function createCounter(){
    let count = 0
    return function(){
        count++
        return count
    }
}

const counter = createCounter()
console.log(counter())  // 1
console.log(counter())  // 2
console.log(counter())  // 3
```

每次调用 `counter()` 操作的都是同一个 `count`，因为闭包把它保留住了。

### 3.2 函数作为参数传递（回调函数）

```js
function fn(){
    let msg = 'Hello Closure'
    setTimeout(function(){
        console.log(msg)  // 回调函数引用了 msg
    }, 1000)
}
fn()  // 1秒后输出 "Hello Closure"
```

`setTimeout` 的回调函数被带到了外部执行，但它仍然能访问 `fn` 内部的 `msg`。

## 四、经典面试题：循环中的闭包

这是我实际练习的代码（[test.js](file:///f:/AAAAIFullStackDevelop/js/闭包/test.js)），完整体验了从"输出 6 个 6"到"输出 1 到 5"的完整过程。

### 4.1 错误写法：输出 6, 6, 6, 6, 6

```js
var arr = []
for(var i = 1; i <= 5; i++){
    arr.push(function(){
        console.log(i)
    })
}
for(let n = 0; n < arr.length; n++){
    arr[n]()
}
```

**为什么全是 6？**

- `var i` 是函数作用域，5 次循环共用**同一个** `i`
- 循环结束时 `i = 6`
- 所有函数引用的都是同一个 `i`，所以都输出 6

### 4.2 解决方案一：IIFE（立即执行函数）

```js
var arr = []
for(var i = 1; i <= 5; i++){
    (function(j){
        arr.push(function(){
            console.log(j)
        })
    })(i)
}
```

通过 IIFE 创建独立作用域，`j` 把每次循环的 `i` 值"固定"下来。

### 4.3 解决方案二：函数包装（我用的方式）

```js
var arr = []
for(var i = 1; i <= 5; i++){
    function fn(j){
        arr.push(function(){
            console.log(j)
        })
    }
    fn(i)
}
for(let n = 0; n < arr.length; n++){
    arr[n]()
}
```

输出：**1, 2, 3, 4, 5** ✅

原理和 IIFE 一样——每次调用 `fn(i)` 都会创建一个新的执行上下文，参数 `j` 复制了当前 `i` 的值，每个内部函数捕获的是自己独有的 `j`。

### 4.4 解决方案三：用 let（最简单）

```js
var arr = []
for(let i = 1; i <= 5; i++){   // var 改成 let
    arr.push(function(){
        console.log(i)
    })
}
for(let n = 0; n < arr.length; n++){
    arr[n]()
}
```

输出：**1, 2, 3, 4, 5** ✅

`let` 在每次循环迭代时都会创建独立的块级作用域绑定，相当于自动帮我们做了上面 IIFE 的事情。

### 4.5 避坑：add()() 的陷阱

再看一个我踩过的坑（[4.js](file:///f:/AAAAIFullStackDevelop/js/闭包/4.js)）：

```js
function add(){
    let count = 0
    return function(){
        count++
        return count
    }
}

// 写法一：输出 1, 2, 3
var bar = add()
for(let i = 0; i < 3; i++){
    console.log(bar())   // 同一个闭包，count 累加
}

// 写法二：输出 1, 1, 1
for(let i = 0; i < 3; i++){
    console.log(add()()) // 每次新建闭包，count 重置为 0
}
```

**写法二**中，每次 `add()` 都创建了一个全新的闭包（新的 `count = 0`），然后立即调用返回的函数，`count` 从 0 变成 1，用完就丢。所以每次都输出 1。

如果想用 `add()()` 实现累加，可以把 `count` 提到外面：

```js
let count = 0
function add(){
    return function(){
        count++
        return count
    }
}
for(let i = 0; i < 3; i++){
    console.log(add()())  // 1, 2, 3
}
```

## 五、闭包的优点与缺点

### 优点

1. **定义私有变量** — 外部无法直接访问闭包内部的变量，只能通过暴露的接口操作

```js
function createPerson(){
    let age = 0           // 私有变量，外部无法直接修改
    return {
        getAge: function(){
            return age
        },
        growUp: function(){
            age++
        }
    }
}
const p = createPerson()
p.growUp()
p.growUp()
console.log(p.getAge())   // 2
console.log(p.age)        // undefined，直接访问不到
```

2. **防止全局变量污染** — 变量限定在函数内部，不会污染全局命名空间

3. **实现模块化** — 将相关功能封装在闭包中，只暴露必要接口

### 缺点

**内存泄漏** — 这是闭包最主要的缺点。

正常情况下，一个函数执行完毕后，它的执行上下文会被销毁，内部变量被回收。但闭包中的变量因为仍然被引用，所以**无法被垃圾回收**，一直占用内存。

如果闭包被全局变量引用，那这块内存将**永远无法释放**：

```js
var baz = foo()  // 闭包被全局变量引用，永远不会被回收
```

### 如何避免？

当闭包不再需要时，手动解除引用：

```js
var baz = foo()
// ... 使用闭包 ...
baz = null    // 断开引用，下次垃圾回收时释放内存
```

## 六、闭包与垃圾回收

用一个形象的比喻来理解：

> 函数执行就像是台上的演员表演，演完了就退场（执行上下文销毁）。但闭包中的变量就像舞台上的道具，虽然演员退场了，但幕后人员（内部函数）还需要这些道具，所以道具不能被清走，得留在那里。

V8 引擎在发现一个函数执行完毕时，会检查：

1. 这个函数内部有没有其他函数引用了它的变量？
2. 如果有，这些内部函数有没有被带到外部？

如果两个条件都满足，引擎就会把被引用的变量**保留在内存中**，这就是闭包的内存开销来源。

## 七、总结

### 一句话记住闭包

> **一个函数"记住"了它外面的变量，即使外面函数执行完了，这些变量依然存在。**

### 闭包三步走

| 步骤 | 说明 | 代码 |
|------|------|------|
| 1 | 外层函数套内层函数 | `function outer(){ function inner(){} }` |
| 2 | 内层函数引用外层变量 | `inner` 中使用外层 `count` |
| 3 | 把内层函数拿出去 | `return inner` 或 `arr.push(inner)` |

### 快速判断是不是闭包

看到以下模式，就是在用闭包：

- ✅ `function a(){ return function(){} }`
- ✅ `arr.push(function(){ console.log(x) })`
- ✅ `setTimeout(function(){ ... }, 1000)` 内部引用了外部变量
- ❌ 普通函数调用，没有内部函数被带到外部

### 注意事项

- 闭包很有用，但**非必要不写闭包**，避免不必要的内存占用
- 用完闭包后记得置 `null`，方便垃圾回收
- `let` 可以简化很多闭包场景（如 for 循环），优先使用
- 理解词法作用域是理解闭包的关键——**函数的作用域看定义位置，不看调用位置**
